핵심 문제 해결 스토리

현업에서 직면했던 도전적인 기술적 과제들과 이를 해결하기 위한 사고 과정,
그리고 백엔드 개발자로서 치열하게 고민한 실질적인 대응 전략을 정리했습니다.

Problem Situation

초기 프로젝트는 Controller 내에서 비즈니스 로직과 SQL 연동이 혼재된 구조였습니다. 코드가 비대해짐에 따라 유지보수 생산성이 저하되었고, 정적 바인딩(Statement) 방식의 데이터 접근으로 인한 SQL 인젝션 보안 취약점 우려가 있었습니다.

Action Plan

로직 파편화 해결을 위해 Controller-Service-Mapper 3계층 아키텍처로 전면 재설계를 주도함. REST API 규약을 정립하고 MyBatis 바인딩 표준화 및 동적 쿼리 기반의 보안 체계를 구축하여 코드 유지보수성과 API 안정성을 확보했습니다.

Core Result

"데이터 접근 계층 분리를 통해 코드 중복을 획기적으로 줄였으며, 운영 유지보수 리드타임을 대폭 단축하여 시스템 확장성을 확보했습니다."

Problem Situation

다수 사용자가 동일 장비에 동시 대여 요청을 보낼 경우, '조회 후 수정(SELECT-then-UPDATE)' 방식으로는 찰나의 시차로 인해 중복 대여가 발생하는 데이터 무결성 이슈를 식별했습니다.

Action Plan

복잡한 분산 락(Lock) 도입 전, DB의 원자적 특성을 활용한 조건부 UPDATE(Conditional Update) 로직으로 구조를 효율화했습니다. WHERE 상태='대여가능' 조건을 쿼리에 포함하고, 영향 행 수(Affected Rows)가 정확히 1건일 때만 성공으로 처리하는 검증 프로세스를 구축했습니다.

Core Result

"수십 건의 동시 요청 환경에서도 데이터 정합성을 100% 보장했으며, 현장 중복 대여 사고를 영구적으로 근절하여 서비스 신뢰도를 극대화했습니다."

Problem Situation

ERP 및 결제 시스템 등 대규모 트래픽과 복잡한 로직이 얽힌 환경에서는 장애 발생 시 원인을 '감'으로 파악하기 어려워 신속한 대응에 한계가 있었습니다.

Action Plan

단순 로그 분석을 넘어 JENNIFER APM 기반의 실시간 모니터링 체계를 적극 활용했습니다. 지연 발생 시 스택 트레이스와 연동된 SQL 실행 계획을 분석하여 병목 구간을 정확히 식별하고 조치했습니다.

Core Result

"원인 분석 리드타임을 최소화하고 데이터 기반의 정밀 트러블슈팅을 정착시켜, 서비스 중단 시간을 최소화하고 운영 안정성을 체계적으로 강화했습니다."
